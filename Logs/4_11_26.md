# Implementaicón de ros2_control

Se usa para controlar las piezas móviles del robot tanto en simulación como en el real, la idea es unificar todo el código para no tener que cambiar una varibles en demasiados códigos (la intención es solo cambiarlo en uno -parametros_robot.yaml- situado en comun/description/config) con esto solo tendríamos que modificar el archivos de parámetros y se actualzaría en todos los códigos.

controllers.yaml se encarga de definir los controladores y de la tradicción para la tracción de las ruedas 

Cambiamos sim.launch.py (en simulación para que cargue las variables definidas en parametros_robot y los controladores de controllers.yaml) para ello debe crear un archivo temporal en simulacion/tmp este archivo actua como fusión entre parametros y controllers de forma que solo se usa en tiempo de ejecución, posteriormente se eliminará. De esta forma podemos definir las dimensiones en parametros y los controladores en controllers, si no habría que definir los parámetros dentro de controllers proque no se puede poner como variables que lean parametros (usamos python para hacer este puente en la fusión)

Cambio rsp.luanch.py para poder usar la variable use_sim y los datos de controller.yaml

En sim.launch.py se elimina del briche el comando cmd_vel porque lo puenteamos en diff_cont_spawner para controlarlo con ros2_control. Añadimos clock para sincronizar el reloj interno de simulación con los cálculo que hace diff_cont, además en controllers lo hacemos en bucle abierto para que no aborte el comando por no tener feedback -pruena con openloop: false- -> falla al cargar el diff_cont 

Ahora el teleop va a pulsos por el timeout para que no avance infinitamente si no se le manda
